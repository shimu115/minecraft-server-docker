# 错误码规范（Error Code Specification）

## 1. 设计原则

项目所有业务状态码统一维护于 `ErrorCode.java` 枚举中，禁止在代码中硬编码数字。

遵循以下原则：

- **一处定义，全局使用**：所有错误码在 ErrorCode 枚举中集中管理。
- **分段分配**：按业务模块分配独立号段，避免冲突，便于定位问题。
- **code 与 msg 强绑定**：每个枚举值同时定义状态码和默认消息。
- **号段预留空间**：每个模块预留充足号段，避免未来扩展时打乱编码。

---

## 2. 号段分配

| 号段 | 模块 | 说明 |
|------|------|------|
| `200` | - | 成功 |
| `10000` ~ `19999` | 通用错误 | 参数校验、服务内部错误等 |
| `20000` ~ `29999` | 认证授权 | 登录、Token、权限相关 |
| `30000` ~ `39999` | 用户 | 用户管理相关 |
| `40000` ~ `49999` | API Key | Key 生命周期管理 |
| `50000` ~ `59999` | 实例 | Minecraft 实例管理 |
| `60000` ~ `69999` | Agent 通信 | 与 Go API 交互相关 |
| `70000` ~ `79999` | 预留：文件管理 | |
| `80000` ~ `89999` | 数据库与备份恢复 | 完整性校验、迁移、备份恢复 |
| `90000` ~ `99999` | 预留：系统配置 | |

各模块内部按 `XX000` 起编，同类错误递增。

## 3. 完整错误码表

### 3.1 成功

| 枚举值 | code | msg |
|--------|------|-----|
| `SUCCESS` | `200` | `ok` |

### 3.2 通用错误（10000 ~ 19999）

| 枚举值 | code | msg | 说明 |
|--------|------|-----|------|
| `BAD_REQUEST` | `10000` | `请求参数错误` | 请求参数格式或内容不正确 |
| `INTERNAL_ERROR` | `10001` | `服务器内部错误` | 未预期的服务端异常 |

### 3.3 认证授权（20000 ~ 29999）

| 枚举值 | code | msg | 说明 |
|--------|------|-----|------|
| `UNAUTHORIZED` | `20000` | `未登录或登录已过期` | Token 缺失或失效 |
| `FORBIDDEN` | `20001` | `无权限执行此操作` | 已登录但无对应权限 |
| `INVALID_CREDENTIALS` | `20002` | `用户名或密码错误` | 登录凭据不正确 |

### 3.4 用户（30000 ~ 39999）

| 枚举值 | code | msg | 说明 |
|--------|------|-----|------|
| `USER_NOT_FOUND` | `30000` | `用户不存在` | 查询的用户不存在 |
| `USERNAME_EXISTS` | `30001` | `用户名已存在` | 创建时用户名冲突 |
| `USER_NOT_BOUND` | `30002` | `用户未绑定任何实例` | 用户无关联实例 |

### 3.5 API Key（40000 ~ 49999）

| 枚举值 | code | msg | 说明 |
|--------|------|-----|------|
| `KEY_NOT_FOUND` | `40000` | `API Key 不存在` | 查询的 Key 不存在 |
| `KEY_ALREADY_EXISTS` | `40001` | `该 API Key 已注册` | 创建时 Key 冲突 |
| `KEY_ALREADY_BOUND` | `40002` | `该 API Key 已被其他实例绑定` | 绑定操作冲突 |
| `KEY_INVALID_FORMAT` | `40003` | `API Key 格式无效，需 UUID v4 格式` | 格式校验失败 |
| `KEY_REVOKED` | `40004` | `该 API Key 已吊销` | Key 已被吊销 |
| `KEY_BOUND_CANNOT_DELETE` | `40005` | `该 Key 已绑定实例，请先解绑再删除` | 删除前校验失败 |

### 3.6 实例（50000 ~ 59999）

| 枚举值 | code | msg | 说明 |
|--------|------|-----|------|
| `INSTANCE_NOT_FOUND` | `50000` | `MC 实例不存在` | 查询的实例不存在 |
| `INSTANCE_NAME_EXISTS` | `50001` | `实例名称已存在` | 创建时名称冲突 |
| `INSTANCE_NOT_BOUND` | `50002` | `当前用户未绑定该实例，无法操作` | 用户无权访问该实例 |

### 3.7 Agent 通信（60000 ~ 69999）

| 枚举值 | code | msg | 说明 |
|--------|------|-----|------|
| `AGENT_UNREACHABLE` | `60000` | `无法连接到 Go API` | 网络不可达 |
| `AGENT_TIMEOUT` | `60001` | `Go API 请求超时` | 请求超时 |
| `AGENT_ERROR` | `60002` | `Go API 返回错误` | Agent 返回非预期结果 |
| `AGENT_REFRESH_FAILED` | `60003` | `刷新 Go API Key 失败` | Key 刷新操作失败 |

### 3.8 数据库与备份恢复（80000 ~ 89999）

| 枚举值 | code | msg | 说明 |
|--------|------|-----|------|
| `DB_INTEGRITY_FAILED` | `80000` | `数据库文件完整性校验失败` | 启动时数据库文件损坏且无法自动恢复 |
| `DB_MIGRATION_FAILED` | `80001` | `数据库迁移失败` | 版本升级迁移脚本执行出错，已回滚 |
| `DB_BACKUP_FAILED` | `80002` | `数据库备份失败` | 迁移前备份创建失败，迁移未执行 |
| `DB_RECOVERY_FAILED` | `80003` | `数据库备份恢复失败` | 用备份恢复后再次校验仍未通过 |
| `DB_STRUCTURE_MISMATCH` | `80004` | `数据库表结构与预期不匹配` | 核心表缺失或无法正常访问 |

## 4. 扩展规范

### 新增错误码步骤

1. 在 `ErrorCode.java` 对应模块号段内追加枚举值
2. code 在当前模块内递增（如用户模块下一个为 `30003`）
3. msg 使用中文，简明描述错误原因
4. 同步更新本文档的错误码表

### 新增模块

如需新增业务模块（如文件管理、备份、日志），按以下规则分配号段：

| 候选号段 | 说明 |
|----------|------|
| `70000` ~ `79999` | 预留：文件管理 |
| `80000` ~ `89999` | 数据库与备份恢复 | 数据库完整性校验、迁移、备份恢复 |
| `90000` ~ `99999` | 预留：系统配置 |

新模块从 `70000` 起按顺序分配，未经评审不应跳号。

### 号段内部分配规则

单个模块内部按以下规则编码：

- `XX000`：资源不存在（NOT_FOUND）
- `XX001`：资源冲突（ALREADY_EXISTS / CONFLICT）
- `XX002`：关联/绑定异常
- `XX003` ~ `XX009`：格式校验、状态异常等
- `XX010` ~ ：扩展使用

## 5. 使用规范

### Controller / Service 中使用

```java
// ✅ 使用枚举值
return ApiResponse.error(ErrorCode.USER_NOT_FOUND);
throw new McPanelException(ErrorCode.KEY_ALREADY_EXISTS);

// ❌ 硬编码数字
return ApiResponse.error(5000, "用户不存在");
throw new McPanelException(30000, "用户不存在");   // McPanelException 不支持直接传 code
```

### 全局异常处理器中的映射

`TryCatchGlobalException` 自动将 `McPanelException` 的 ErrorCode 转换为 `ApiResponse.error`：

```java
// McPanelException 携带的 ErrorCode
throw new McPanelException(ErrorCode.USER_NOT_FOUND);

// 全局处理器自动转换为
// ApiResponse { code: 30000, msg: "用户不存在", data: null }
```

---

## 6. 禁止事项

- ❌ 在业务代码中直接使用数字状态码（`ApiResponse.error(500, "...")`）
- ❌ 在 ErrorCode 枚举外定义业务状态码常量
- ❌ 跳过 ErrorCode 直接 `new McPanelException(null, "自定义消息")`
- ❌ 不同模块混用号段（如在用户模块使用 4xxxx 号段）
- ❌ 新增错误码但不更新本文档

---

## 7. 核心原则

1. **集中管理**：所有错误码统一在 `ErrorCode.java` 中定义
2. **分段隔离**：每个业务模块独立号段，互不冲突
3. **强绑定**：code 与 msg 在枚举中成对定义，不可拆分使用
4. **可扩展**：号段预留充足空间，新增错误码在当前模块内递增
5. **一处修改**：错误码变更只需修改枚举定义，所有引用自动生效
